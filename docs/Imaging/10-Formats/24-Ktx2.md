---
title: KTX 2.0
description: Read KTX 2.0 GPU textures, their mip levels, array layers and cube faces, uncompressed or block-compressed with BCn, ETC2, EAC, ASTC and Basis Universal.
---

KTX 2.0 files (`.ktx2`, Khronos Texture) hold the textures of GPU applications and glTF models: images of one to three
dimensions, arrays of them, cube maps and their mip levels, uncompressed or block-compressed, and often supercompressed.
The library reads them: every level, layer, face and depth slice is an entry of an
[ImageCollection](cref:Meziantou.Framework.Imaging.ImageCollection), and [Image.Load](cref:Meziantou.Framework.Imaging.Image.Load) gives the base level of the first face of the first layer. It does
not write them.

## What is read

| | Reading |
| --- | --- |
| Textures | 1D, 2D and 3D textures, arrays, cube maps and cube map arrays, with their mip levels |
| Uncompressed formats | 8-bit and 16-bit UNORM and sRGB, 16-bit and 32-bit floats, the packed formats (`R5G6B5`, `R4G4B4A4`, `A2B10G10R10`, `B10G11R11`, `E5B9G9R9`, ...) |
| Block-compressed formats | BC1 to BC7 (S3TC, RGTC and BPTC, with the block decoders of [DDS](21-Dds.md)), ETC2 (RGB, punchthrough alpha, RGBA), EAC (R11 and RG11, unsigned and signed), ASTC 2D of every block size (sRGB, UNORM, HDR) |
| Basis Universal | ETC1S (BasisLZ supercompression, P-frames of videos included) and UASTC, decoded straight to RGBA |
| Supercompression | Zstandard and ZLIB |
| Metadata | `KTXswizzle` applied, `KTXorientation` reported as the orientation, `KTXanimData` as an animation, the color labels of the data format descriptor, and every key reported |

PVRTC blocks, the YCbCr formats, 3D ASTC blocks and premultiplied alpha are rejected with an
[UnsupportedImageFeatureException](cref:Meziantou.Framework.Imaging.UnsupportedImageFeatureException). See [Limitations](../12-Limitations.md).

## Load a texture and its levels

<!-- ref:../../../samples/Meziantou.Framework.Imaging.Samples/Examples.cs;region=Imaging_Ktx2;format=md-fenced-code-block;dedent=true -->
```csharp
public static IReadOnlyList<string> ExportKtx2Levels(string ktx2Path, string outputDirectory)
{
    // Image.Load decodes the base level of the first face of the first layer (or the frames of an animation)
    using (var texture = Image.Load(ktx2Path))
    {
        texture.Save(Path.Combine(outputDirectory, "base.png"));
    }

    // Every level, layer, face and depth slice is an entry of a collection, decoded on demand
    var files = new List<string>();
    using var collection = ImageCollection.Load(ktx2Path);
    foreach (var entry in collection.Entries)
    {
        if (entry.TextureSurface is { ArrayIndex: 0, Face: null or CubeMapFace.PositiveX, DepthSlice: 0, MipLevel: var level })
        {
            using var image = entry.Decode();
            var path = Path.Combine(outputDirectory, $"level-{level}.png");
            image.Save(path);
            files.Add(path);
        }
    }

    return files;
}
```
<!-- endref -->

The entries of the collection are ordered by layer, then face, then level, then depth slice, and
[TextureSurface](cref:Meziantou.Framework.Imaging.ImageCollectionEntry.TextureSurface) tells which one an entry is: its
[MipLevel](cref:Meziantou.Framework.Imaging.TextureSurface.MipLevel), [ArrayIndex](cref:Meziantou.Framework.Imaging.TextureSurface.ArrayIndex), [Face](cref:Meziantou.Framework.Imaging.TextureSurface.Face) (a [CubeMapFace](cref:Meziantou.Framework.Imaging.CubeMapFace) of a cube map, `null` otherwise) and
[DepthSlice](cref:Meziantou.Framework.Imaging.TextureSurface.DepthSlice). Loading the collection reads the structure of the file only; the texels of an entry are
read when it is decoded. [ImageInfo.CollectionEntryCount](cref:Meziantou.Framework.Imaging.ImageInfo.CollectionEntryCount) gives the number of entries without loading a collection. An
array texture with `KTXanimData` loads as an animation of its layers, with the duration and the loop count of the key.

## Pixels and colors

- A format decodes to the pixel format that holds its samples: 8-bit formats, ETC2, ETC1S, UASTC and ASTC sRGB to
  8-bit pixels, 16-bit formats and EAC to 16-bit pixels, floats and ASTC HDR to
  [RgbaHalf](cref:Meziantou.Framework.Imaging.RgbaHalf) or [RgbaFloat](cref:Meziantou.Framework.Imaging.RgbaFloat). ASTC UNORM textures decode to
  [RgbaHalf](cref:Meziantou.Framework.Imaging.RgbaHalf), the default of KTX, or to 8-bit pixels when the file says
  `KTXastcDecodeMode` is `unorm8`.
- The channels a format lacks are 0, and alpha is 1, as a GPU samples them: an `R8` texture loads red. A luminance
  texture says so with the swizzle `rrr1`, which the library applies, and loads gray.
- The transfer function of the data format descriptor is the color label: sRGB formats are labeled sRGB, and UNORM
  formats usually linear ([ColorTransferFunction.Linear](cref:Meziantou.Framework.Imaging.Metadata.ColorTransferFunction.Linear)). Other primaries are a CICP description.
- `KTXorientation` is reported as [ImageMetadata.Orientation](cref:Meziantou.Framework.Imaging.Metadata.ImageMetadata.Orientation): `ru` (the first row is the bottom one) is
  [ExifOrientation.BottomLeft](cref:Meziantou.Framework.Imaging.Metadata.ExifOrientation.BottomLeft). Only [AutoOrient](cref:Meziantou.Framework.Imaging.ImageProcessingExtensions.AutoOrient) applies it.
- [ImageMetadata.Ktx2Header](cref:Meziantou.Framework.Imaging.Metadata.ImageMetadata.Ktx2Header) reports the format, the sizes and the key/value data of the file.

## Pitfalls

- UNORM textures are labeled linear, which PNG, JPEG and most formats cannot store: saving one follows
  [MetadataHandling](cref:Meziantou.Framework.Imaging.Formats.MetadataHandling), which rejects it by default. A normal map or another data texture is not a color: set its
  [TransferFunction](cref:Meziantou.Framework.Imaging.Metadata.ImageMetadata.TransferFunction) to [Srgb](cref:Meziantou.Framework.Imaging.Metadata.ColorTransferFunction.Srgb) to save the samples as they are, or convert real colors with
  [ConvertColorProfile](cref:Meziantou.Framework.Imaging.ImageProcessingExtensions.ConvertColorProfile).
- A UASTC texture with the sRGB transfer function is decoded as an ASTC sRGB decoder decodes it (section 25.7.2.8 of
  the Khronos Data Format Specification). KTX-Software and basisu decode UASTC with the linear expansion whatever
  the transfer function, so their samples can differ by 1.
- Illegal ASTC blocks, which the specification decodes to magenta, are rejected with an
  [InvalidImageContentException](cref:Meziantou.Framework.Imaging.InvalidImageContentException), and so are HDR blocks in an LDR texture.
- [Image.OpenReader](cref:Meziantou.Framework.Imaging.Image.OpenReader) rejects KTX 2.0: use [ImageCollection](cref:Meziantou.Framework.Imaging.ImageCollection) or [Image.Load](cref:Meziantou.Framework.Imaging.Image.Load). The asynchronous loads buffer the file.
- There is no lenient decoding for KTX 2.0: a truncated or malformed file is rejected.
