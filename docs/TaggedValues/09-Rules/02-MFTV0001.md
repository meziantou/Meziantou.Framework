---
title: "MFTV0001: Do not compare values with different tags"
description: Two values with different tags are compared, for instance an order id with a project id.
---

## Cause

Two values with different tags are compared, for instance an order id with a project id. Such a comparison is almost
always a bug: it is false for every pair of real values.

The rule covers `==`, `!=`, `<`, `<=`, `>`, `>=`, tuple equality, `Equals`, `CompareTo`, `EqualityComparer<T>.Equals`,
`Comparer<T>.Compare`, `string.Equals(a, b, comparison)`, and `a.Equals(b, comparison)`:

<!-- ref:../../../samples/Meziantou.Framework.TaggedValues.Samples/Rules/ComparedValues.cs;region=TaggedValues_MFTV0001;format=md-fenced-code-block;dedent=true -->
```csharp
_ = order.Id == project.Id;                         // MFTV0001
_ = order.Id.Equals(project.Id);                    // MFTV0001
_ = orders.Where(item => item.Id == project.Id);    // MFTV0001
```
<!-- endref -->

The message names both values and their tags:

```text
property 'Order.Id' is [ValueTag("OrderId")] and is compared with property 'Project.Id', which is [ValueTag("ProjectId")]
```

## How to fix

Compare the value with a value that has the same tag:

<!-- ref:../../../samples/Meziantou.Framework.TaggedValues.Samples/Rules/ComparedValues.cs;region=TaggedValues_MFTV0001_Fixed;format=md-fenced-code-block;dedent=true -->
```csharp
_ = order.ProjectId == project.Id;
_ = order.ProjectId.Equals(project.Id);
_ = orders.Where(item => item.ProjectId == project.Id);
```
<!-- endref -->

When the values are right and a declaration is tagged incorrectly, fix the [\[ValueTag\]](cref:Meziantou.Framework.TaggedValues.ValueTagAttribute) of that declaration. When a
declaration legitimately holds both kinds of values, give it both tags: `[ValueTag("OrderId", "ProjectId")]`. See
[Accept several tags](../03-TaggingValues.md#accept-several-tags).
