---
title: "MFTV0006: Add an explicit tag to disambiguate the conventional tag"
description: Several types with the same name declare an Id member, so the naming convention gives their ids the same tag.
---

## Cause

This rule is only reported when the [naming conventions](../07-NamingConventions.md) are enabled.

The convention tags a member named `Id` with the name of its type. When two types have the same name in different
namespaces, their ids get the same tag, and the analyzer cannot tell them apart:

<!-- ref:../../../samples/Meziantou.Framework.TaggedValues.Samples/NamingConventions/Sales/Order.cs;region=TaggedValues_MFTV0006_Sales;format=md-fenced-code-block;dedent=true -->
```csharp
public sealed class Order
{
    public Guid Id { get; set; } // MFTV0006
}
```
<!-- endref -->

<!-- ref:../../../samples/Meziantou.Framework.TaggedValues.Samples/NamingConventions/Billing/Order.cs;region=TaggedValues_MFTV0006_Billing;format=md-fenced-code-block;dedent=true -->
```csharp
public sealed class Order
{
    public Guid Id { get; set; } // MFTV0006
}
```
<!-- endref -->

The rule is reported on each member:

```text
property 'Sample.NamingConventions.Billing.Order.Id' and property 'Sample.NamingConventions.Sales.Order.Id' both infer the tag 'OrderId' from their type name; add an explicit [ValueTag] with a distinct tag to at least one of them
```

## How to fix

Add an explicit [\[ValueTag\]](cref:Meziantou.Framework.TaggedValues.ValueTagAttribute) with a distinct tag to at least one of the members, for instance
`[ValueTag("BillingOrderId")]` on `Billing.Order.Id`. Explicit tags always win over the conventions.
