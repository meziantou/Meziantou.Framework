---
title: "MFTV0007: Remove the redundant value tag"
description: A ValueTag attribute declares the tag the naming convention already infers.
---

## Cause

This rule is only reported when the [naming conventions](../07-NamingConventions.md) are enabled. Its severity is Info.

The [\[ValueTag\]](cref:Meziantou.Framework.TaggedValues.ValueTagAttribute) attribute declares the tag the naming convention already infers:

<!-- ref:../../../samples/Meziantou.Framework.TaggedValues.Samples/NamingConventions/NamingConventions.cs;region=TaggedValues_MFTV0007;format=md-fenced-code-block;dedent=true -->
```csharp
public sealed class Invoice
{
    [ValueTag("CustomerId")] public Guid CustomerId { get; set; } // MFTV0007
}
```
<!-- endref -->

The property is named `CustomerId`, so the convention already tags it `"CustomerId"`.

The rule is not reported when the member overrides or implements a tagged member: without the attribute, the tags of
the base member would win over the convention.

## How to fix

Remove the attribute. The code fix removes it.
