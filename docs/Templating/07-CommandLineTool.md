`Meziantou.Framework.Templating.Tool` renders a template file without writing code: use it in scripts and builds to
generate source code or configuration files.

## Install the tool

Install it as a global tool:

<InstallDotnetTool Id="Meziantou.Framework.Templating.Tool" />

## Render a template

`--input` is the template file. The text is written to the standard output:

```bash
Meziantou.Framework.Templating.Tool --input template.txt
```

Add `--output` to write it to a file instead. The folder of the file is created if needed:

```bash
Meziantou.Framework.Templating.Tool --input template.txt --output generated/result.txt
```

The template uses the [syntax](03-TemplateSyntax.md) of the library. It receives no argument: compute the data it needs
in its code blocks, for instance by reading a file.

## Generate a file next to the template

A template can name the extension of the file it generates. Here, the `outputextension` directive asks for a `.g.cs`
file:

<!-- ref:../../tests/Meziantou.Framework.Templating.Tool.Tests/Examples/Weekdays.template;format=md-fenced-code-block;language=text -->
```text
<%@ outputextension .g.cs %>
// <auto-generated />
namespace Sample;

public static class Weekdays
{
<% foreach (var day in Enum.GetValues<DayOfWeek>()) { %>
    public const string <%= day %> = "<%= day.ToString().ToLowerInvariant() %>";
<% } %>
}
```
<!-- endref -->

```bash
Meziantou.Framework.Templating.Tool --input Weekdays.template
```

The tool writes `Weekdays.g.cs` in the folder of the template. Its name is the name of the template with the extension
replaced:

<!-- ref:../../tests/Meziantou.Framework.Templating.Tool.Tests/Examples/Weekdays.g.cs;format=md-fenced-code-block;language=csharp -->
```csharp
// <auto-generated />
namespace Sample;

public static class Weekdays
{
    public const string Sunday = "sunday";
    public const string Monday = "monday";
    public const string Tuesday = "tuesday";
    public const string Wednesday = "wednesday";
    public const string Thursday = "thursday";
    public const string Friday = "friday";
    public const string Saturday = "saturday";
}
```
<!-- endref -->

The lines that only hold a directive or a statement block leave no empty line; see
[Line breaks](03-TemplateSyntax.md#line-breaks). `--output` takes precedence over the directive.

## Use T4-style templates

The tool also reads templates written with the delimiters of T4, `<#` and `#>`, and the `output` directive of T4. It
detects them when the file contains a complete `<# … #>` block and no `<%`:

<!-- ref:../../tests/Meziantou.Framework.Templating.Tool.Tests/Examples/Greeting.tt;format=md-fenced-code-block;language=text -->
```text
<#@ output extension=".txt" #>
<# foreach (var name in new[] { "Ada", "Grace" }) { #>
Hello <#= name #>!
<# } #>
```
<!-- endref -->

Rendering `Greeting.tt` writes `Greeting.txt`:

<!-- ref:../../tests/Meziantou.Framework.Templating.Tool.Tests/Examples/Greeting.txt;format=md-fenced-code-block;language=text -->
```text
Hello Ada!
Hello Grace!
```
<!-- endref -->

Only the delimiters and the `extension` of the `output` directive come from T4: the code blocks and the other
directives follow the syntax of the library. The T4 `import`, `assembly` and `template` directives are ignored; use
`<#@ using Namespace #>` and `<#@ reference path #>` instead. `include` adds a C# file, not a template.

## Choose other delimiters

`--start-code-block-delimiter` and `--end-code-block-delimiter` set the delimiters:

```bash
Meziantou.Framework.Templating.Tool --input template.txt --start-code-block-delimiter "{{" --end-code-block-delimiter "}}"
```

Pass both, unless you choose one of the known pairs: `--start-code-block-delimiter "<#"` alone implies `#>`, and
`<%` implies `%>`.

## Options

| Option | Description |
| --- | --- |
| `--input <path>` | The template file. Required. |
| `--output <path>` | The file to write. When omitted, the file named by an output directive, or the standard output. |
| `--start-code-block-delimiter <text>` | The start delimiter of code blocks. When omitted, inferred from a known end delimiter or detected from the template. |
| `--end-code-block-delimiter <text>` | The end delimiter of code blocks. When omitted, inferred from a known start delimiter or detected from the template. |
| `--output-encoding <name>` | The encoding of the output file: `utf8` (the default, without byte order mark), `utf8-bom`, or a .NET encoding name such as `utf-16`, `unicode` or `utf-32`. |
| `--line-ending <LF\|CRLF\|CR>` | Converts the line breaks of the output. By default, the output keeps the line breaks of the template. |
| `-?`, `-h`, `--help` | Shows the help. |
| `--version` | Shows the version of the tool. |

## Errors

The tool exits with code 0 when it succeeds, and 1 when it fails, with a message on the standard error:

- a missing input file, an empty delimiter, a single unknown delimiter, an unknown line ending or encoding;
- a compilation error of the template, reported with the path of the template, the line and the column of the error;
- an exception thrown by the code of the template, reported as `path(line,column): error: message`, at the position of
  the code that threw it.
