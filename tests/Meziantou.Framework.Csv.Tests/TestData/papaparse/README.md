# Papa Parse

Offline fixtures from https://github.com/mholt/PapaParse/tree/7fe53c8c46cf00f7b59db403af4f2a91eaa54dc4, licensed under MIT; see LICENSE.txt.

cases.json contains the cases of `CORE_PARSER_TESTS` (named `core/<description>`, run by `new Papa.Parser(config).parse(input)`) and `PARSE_TESTS` (named `parse/<description>`, run by `Papa.parse(input, config)`) of `tests/test-cases.js`: the input, the configuration, the expected data, and the type and code of each expected error (`Quotes/MissingQuotes`, ...). A second case with the same description gets a ` (2)` suffix. The 10 cases whose configuration holds a function (`transform`, `transformHeader`, a delimiter or a `dynamicTyping` callback) are left out. These fixtures are independent expected parser results, not outputs generated by this library. `Meziantou.Framework.Csv.Fuzz` embeds the same file as seeds.

`CsvTestSuiteTests` does not run the cases that use an option the reader does not have (multi-character separators or comment prefixes, `skipEmptyLines: "greedy"`, `dynamicTyping`, `skipFirstNLines`, `delimitersToGuess`, an `escapeChar` other than the quote), and lists the cases whose expected data is a choice of Papa Parse that the reader does not make.

To refresh, clone the repository at the new commit, evaluate the two array literals of `tests/test-cases.js` in a context that defines `RECORD_SEP` (U+001E), `UNIT_SEP` (U+001F) and `BASE_PATH`, and write each case whose configuration is JSON data.
