# css-parsing-tests

Offline fixtures from https://github.com/SimonSapin/css-parsing-tests/tree/203ce36bffd617db7f118c551e32794561fb273d, dedicated to the public domain under CC0; see LICENSE.txt.

The corpus is the one tinycss2 and rust-cssparser are tested against. Each file is a JSON array alternating an input and the result expected from one entry point of CSS Syntax Level 3; README.rst in the upstream repository describes the format. These are independent expected parser results, not outputs generated by this library.

The files kept are those for the entry points this parser has: `component_value_list`, `one_component_value`, `one_declaration`, `blocks_contents`, `one_rule`, `stylesheet`, and `An+B`. `declaration_list` and `rule_list` test entry points CSS Syntax no longer has, and the `color_*` files test a value grammar this parser does not implement.

The corpus was written for the 2021 Candidate Recommendation of CSS Syntax Level 3, which still had unicode-range tokens everywhere and tokens for `~=` and `||`. `CssParsingTestsSuiteTests` projects the tree onto the corpus format, joining the delims that made those tokens, and lists the remaining differences in `KnownDeviations`.

To refresh, replace the files with those of a newer commit, update the commit above, and run the tests: a known deviation that starts to match fails, and so does a new case that does not.
